# Milo.Native.Windows

This unelevated, Windows-only helper is the native boundary for Milo's selected-window flow.

## Protocol

The helper reads one UTF-8 JSON object per line from stdin and writes one JSON object per line to stdout. Each request line is bounded to 16 KiB measured after UTF-8 encoding (not UTF-16 code units); oversized lines are drained and rejected. Unknown operations and unknown JSON fields fail closed.

Currently supported:

```json
{"id":"0123456789abcdef0123456789abcdef","type":"list_windows"}
```

The `list_windows` response contains opaque HWND/PID/process-creation identities only. It never returns window titles, process names, paths, UI text, screenshots, or diagnostics. Selection identity validation is held in memory only until the next enumeration; rooted UI Automation extraction is available through the separate `extract_text` request. Capture/OCR remains a later phase.

After a fresh `list_windows` call, the caller may request a bounded local text snapshot for one of the returned HWND/PID/process-creation tuples:

```json
{"id":"0123456789abcdef0123456789abcdef","type":"extract_text","hwnd":123456,"pid":4321,"processCreationTime":"134000000000000000","maxChars":6000}
```

Every valid request requires a 32-character lowercase hexadecimal `id`; the same `id` is returned in the response so the caller can correlate replies. IDs are generated by Electron and are not user-provided content. The process-creation FILETIME is encoded as a decimal string because it exceeds JavaScript's safe integer range.

`extract_text` is fail-closed: the exact tuple must have been returned by the helper's latest enumeration, the HWND must still be visible and belong to the same PID, the process creation FILETIME must still match, and `maxChars` must be between 256 and 12,000 (6,000 by default). Windows UI Automation runs inside the helper and returns only bounded normalized text plus a truncation flag. The helper does not save, cache, log, OCR, upload, or otherwise retain the extracted text. Electron must send it only to the local context normalizer when the user explicitly asks Milo for a suggestion.

`capture_text` accepts the same identity tuple plus `language` (`en` or `it`). It creates a `GraphicsCaptureItem` for that exact HWND, captures one bounded frame with `Direct3D11CaptureFramePool`, and runs `Windows.Media.Ocr` locally when the requested recognizer is installed. It never accepts a monitor, display, rectangle, picker result, or whole-desktop target. The frame, software bitmap, capture session, and frame pool are closed immediately; only bounded OCR text and a truncation flag cross stdout.

The helper has no listener, network access, shell surface, filesystem commands, elevation request, or arbitrary process invocation. It must be launched only by the signed Electron application after the protocol and identity checks are complete. The helper does not send messages or control the selected application.

## Electron integration status

The Electron-side fixed-path process launcher, bounded protocol adapter, child lifetime supervision, and shutdown-on-dispose behavior are implemented and unit-tested in `apps/desktop/src/main/native-helper-client.ts`, but the adapter is not yet wired into the desktop flow. An authenticated helper session token and shutdown-on-window-close wiring remain pending integration. Until then, the current picker remains Electron's local window enumeration boundary. No caller should treat a raw helper process or an arbitrary HWND/PID pair as trusted.

Build with the repository-pinned .NET SDK:

```text
dotnet build native/windows/Milo.Native.Windows.csproj --configuration Release
```
